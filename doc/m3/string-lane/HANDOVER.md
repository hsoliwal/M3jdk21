# String lane handover

How to read this file:

- It is for the next agent, human or LLM, that continues the M3JDK String work.
- It states the invariants first, then every owner directive with its status, then the order of the pending work.
- Facts come from the landed PRs. Each PR number is an M3jdk21 pull request unless another repository is named.
- Decision numbers refer to the owner decisions, recorded in order in `feedback-string-absorb-decisions-20261116` of the owner's agent memory.

## 1. Invariants (never break; a change that would break one needs the owner)

1. **Everything converges into M3JDK.** That means java.base, OpenJDK layout, `src/<module>/share/classes`, with no new `m3/` source folders. A string operation becomes a public `java.lang.String` method, family by family.
2. **String layout** (decision 47, #3258, #3260): `private final byte[] value` holds the bytes and `private final char[] chValue` holds the chars of every String.
   - Both are filled at construction:
     - by all 18 Java constructor paths;
     - by the VM's `create_from_unicode`, `create_from_str` and `create_from_symbol`.
   - `chValue` never leaves `String`: `getChars` and `toCharArray` copy out of it.
   - C2's `OptimizeStringConcat` defaults to off, because it builds Strings without a constructor.
   - The gate is `test/jdk/java/lang/String/StringLayoutInvariantTest.java`. The design is `STRING_LAYOUT_INVARIANT.md`.
3. **Family method rules** (decisions 31-33):
   - Each method follows the donor's semantics exactly, proven against the donor or the language itself as oracle.
   - When donors disagree, each rule gets its own name, overload or enum value.
   - Null arguments throw NullPointerException, except for static null-safe methods.
   - An unchanged result returns `this`. Range results use `substring`, which makes them M3 slices.
   - Scans use bulk windows (`getChars` into a `char[]` of `SCAN_WINDOW` units) or the Latin-1 byte path. A surrogate pair is never split across windows, and there is never a `charAt` per unit over the whole text.
   - Each method's Javadoc carries `@apiNote This method is an M3JDK addition to the {@code String} API.` and `@since 21`.
4. **Proof rule** for every family:
   - The family texts go into the STOCK JDK 21 `String.java` with an `m3()` shim over `M3StringStub`, compiled with `javac -Xlint:all,-this-escape -Werror`.
   - The proof runs in 3 modes: flat; `-Dm3.stub.force=true -Dm3.stub.facts=true`; `-Dm3.stub.force=true`. Each mode runs with compact strings on and off.
   - Alphabets include two surrogate pairs sharing the high half (`0xD835 0xDD1E`, `0xD835 0xDD1F`), lone halves, and window-seam texts with the deciding unit at 505..520 and 1018..1030.
   - The donor's own tests are ported (`port_donor_tests.py`), and the JUnit runs pass in all six runs.
5. **Public API** (decisions 32, 48): String methods of an admitted family are admitted. Any other new public type or member needs the owner, per the no-public-sprawl rule. The 6 escape enums are admitted (decision 48).
6. **Regex** (decision 46): every regex carries a spec row with these fields: id, pattern, flavour, language and version, source, licence, positive and negative examples, oracle.
   - A regex without a row fails the gate. Product String code uses no regex.
7. **Lexicons** (decisions 44, 45): there is one lexicon per language version, generated by a CPU tool from the published grammar and never hand-typed.
   - Each lexicon compiles at build time into precomputed tables: a DFA over a Latin-1 class table, plus a keyword perfect hash.
   - Nothing is compiled at run time.
8. **Atoms and patterns** (decision 41): every landed family gets an atom ledger and pattern rows (`record/<leaf>/ATOMS.tsv`, `PATTERNS.tsv`, through `tools/atom_ledger.py`). No pattern marks go into product code.
9. **Logger** (decision 29): JUL is the default logger.
10. **Commits:** no AI co-author trailers. The owner's e-mail address stays private. A deletion needs the owner's confirmation.

## 3. How to land a family (tools in the record, `record/tools/`)

1. A workflow drafts up to 4 families at once, each in its own `draft-<key>/` folder: method text, `String.head.java`, `proof/`, JUnit tests, donor tests, spec tables, `NOTES.md` and `REGEX_SPEC.tsv`.
2. `tools/refresh_family_texts.py` rebuilds the current text of every landed family and checks each text occurs once in master. Rerun it whenever a recipe edits family code.
3. `tools/integrate_family.sh <draft> <leaf> <key> <donor-jars>` re-proves the draft on current master.
4. `tools/land_family.sh` writes the atom ledger, the record and the `ABSORB_PLAN.md` row, then commits through `build_and_gate.sh` (naming gates), pushes and opens the PR.
5. `merge_all.py` merges the PR. It honours `MERGE_HOLD.tsv` and `[HOLD]` titles.

For a change to `String.java` outside a family, use `layout-invariant/compile_closure.sh`. It compiles master's `String.java` with its 45-file M3 closure against the stock `java.base` under `-Werror`; reuse it before every String PR.
