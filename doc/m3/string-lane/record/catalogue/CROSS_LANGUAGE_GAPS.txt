WebFetch returns paraphrases from a summarizer that limits quotes. ABNF and code-point ranges came through that summarizer (C23 is the exception: it was read verbatim with pdftotext). Re-check the exact production text in the raw RFC/W3C pages before implementing any kernel.
XSD 1.1 Part 2: the Appendix G regular-expression rules were not in any chunk read (offsets 0-500000; the chunk where they should be came back truncated). The definitions of \i \c \s \d \w and the implicit-anchoring rule are therefore not confirmed, and no pattern-facet row was added. The summarizer's restriction order for the whiteSpace facet (preserve, collapse, replace) looked garbled and was not used.
XML 1.0: the productions for comments [15] and CDATA sections [18]-[21] were not extracted, so they have no rows. The ']]>' rule appears only under CharData [14].
WHATWG HTML: only §13.3 'Escaping a string' and §13.2.5.77-84 (character reference states) were read. The named character references table (entities.json) was not fetched.
CommonMark: §4.5 fenced code block info strings were not read. The email-autolink row points to the HTML5 regex the spec quotes but does not reproduce it.
YAML 1.2.2: the exact c-printable ranges ([1]) and the ns-uri-char punctuation list ([39]) were summarized, not quoted. The listed ranges come from the production numbers and should be re-checked.
TOML: the exact list of control characters that must be escaped (e.g. whether U+007F is included) was not quoted, so the row says only 'control characters other than tab'.
java.util.Properties: the Javadoc does not document escaping of \t \n \r \f for store(Writer). The row reports the documented rules only.
INI has no specification. The INI rows use Win32 GetPrivateProfileString and Python configparser conventions, all tagged OTHER.
POSIX §2.14 Pattern Matching Notation (glob/fnmatch) was not in the chunk read at offset 180000, so it has no row.
UTS #10: §11 (Searching and Matching) and §12.2 (conformance test file names) were not reached; the page read covers characters 0-100000 of 221074. UAX #29: the page does not name the Tests29 files. The test-file names in the oracle fields are therefore unconfirmed.
SQL: ISO/IEC 9075 is not freely available. The SQL rows rely on PostgreSQL 18 docs, which state what is standard and what is a PostgreSQL extension. The page does not say whether U&'...' escapes are standard.
C: N3220 is the C23 working draft, not the published ISO 9899:2024. The PDF was saved by WebFetch and read locally with pdftotext.
JSON Schema format rows cite RFC 5321, 6531, 5890/5891, 2673, 4291, 3987 and 6570 and the relative-JSON-pointer draft only through the JSON Schema page; those documents were not fetched. RFC 3339, 6901, 9562 and 1123 were fetched.
RFC 3986 IPv6: whether '::' stands for zero or more groups or one or more groups was not confirmed from the ABNF text. The row says 'at most one :: compression'.

How the pages were read: 4 index pages (Kotlin, .NET String, Rust str, Go strings) went through WebFetch, which stopped at 100K characters. All listed URLs were then downloaded with curl into the scratchpad and parsed with Python scripts (member tables, signatures, doc briefs). So every row comes from a page that was fetched, but most were parsed by script rather than read through WebFetch.
