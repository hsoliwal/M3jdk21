# Catalogue-driven refinement of M3AST

The user reinforced LeetCode and HackerRank as algorithm-discovery references
during final publication. This additive catalogue records problem categories,
preconditions, primitive-storage candidates, complexity and actual M3AST fit.
It does not amend any frozen compiler/provider output or qualification receipt.

Read the official problem descriptions, use original implementation reasoning,
and do not copy unreviewed solution code. A candidate must match the receiving
owner's semantics before a recipe-produced code change is admitted. Preserve
ordered source identity, original compiler ownership, callback lifetime and
existing cache/swap authority. Performance claims require measurements on the
receiving workload in addition to correctness proofs.

This documentation-only leaf follows the already-qualified source-seal and
shared-task implementation. Its public custody mirror must match exactly. The
new evidence is a category review, not a claim that every listed algorithm was
implemented, benchmarked, or accepted into the compiler.
