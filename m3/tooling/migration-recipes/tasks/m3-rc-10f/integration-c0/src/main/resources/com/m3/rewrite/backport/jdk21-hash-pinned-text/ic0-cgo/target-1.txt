## Java 21 compatibility audit

JDK21 already provides:

- virtual threads / `Thread.ofVirtual()`;
- `SharedSecrets.getJavaUtilCollectionAccess()`;
- `JavaUtilCollectionAccess.listFromTrustedArrayNullsAllowed(...)`;
- `Nodes.castingArray()`.

JDK24 `GathererOp` imports `jdk.internal.invoke.MhUtil`, which is not present in the JDK21 target.
M3 adapts only that helper use to a local `MethodHandles.Lookup.findVarHandle(...)` wrapper with
equivalent fail-fast `InternalError` behavior. Importing the unrelated post-21 `MhUtil` utility is
not required by the Gatherer contract.

## Pinned Java parser adaptations

The Gatherer and Gatherers donor templates express nine inline documentation
examples as `<pre>{@code ...}</pre>` in place of `{@snippet lang = java: ...}`
for the pinned OpenRewrite Java 21 8.17.1 parser. The example bodies and all
executable/API bytes in these two templates remain unchanged.

`GatherersMapConcurrentTest` retains both original concurrency scenarios and
every assertion. Its two guarded `Integer` switch labels are lowered to an
explicit `if (i == streamSize)` / `else` inside the existing default arm; the
`case 1` arm is unchanged. This adaptation preserves selector/null behavior
and all original arm bodies. The unadapted labels trigger a ParseError because
the pinned parser prints `defaultcase`.

The bounded parser trial checked all 15 donor templates and four sealed
beforeimages as typed, byte-exact compilation units. Its separate structural
control retained all six original switch payload arms, checked 2,620 selector
pairs and rejected four negative controls. These source/parser controls do not
qualify the full recipe receiver, concurrent runtime behavior, jtreg, or a built
JDK image. The recipe continues to require typed Java and exact byte round trips.

## Contract / scope

`Stream.gather(Gatherer)` and the public Gatherer/Gatherers APIs are additive public `java.base`
API. Mutation authority is therefore `LIBRARY_API`, even though individual source edits are
mechanically decomposable.
