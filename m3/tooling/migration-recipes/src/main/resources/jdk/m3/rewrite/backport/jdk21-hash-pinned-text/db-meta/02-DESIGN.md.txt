# M3 database and parser contract boundary

## Intent and ownership

Strengthen the existing M3IndexDB, rather than create another database or source
parser. This packet addresses the observed database admission blocker from
workflow run 37176370151/job111359699365: 15 JUnit tests passed, while measured
line/branch ratios were 0.92/0.80 against the unchanged0.99 thresholds.

M3IndexDB remains the semantic-index owner. Its present implementation is a
content-addressed blob/ref store and immutable snapshot graph, not a complete
transactional SQL database. Durability, concurrent-reader/writer ownership,
migration, index paging and recovery need their own evidence before being claimed.

Source parsing remains with the existing javac/OpenRewrite owners. A binary
semantic-snapshot decoder is not a replacement Java parser. The partial-tree
integration should preserve original source, trivia, type information, grammar/
classpath fingerprints and unresolved/error nodes. A syntax tree or normalized
hash alone does not certify type correctness or semantic equivalence.

## This packet

Add three independent JUnit suites for:
1. persisted artifact/ref/blob corruption, lifecycle and failed publication;
2. actual encoded snapshot truncation/header/count/ordinal boundaries;
3. semantic identity, ordered roles, empty compositions and query contracts.

Production source, the15 existing tests, Maven thresholds and plugin configuration
remain unchanged. Tests operate only in JUnit temporary directories. They never
remove security providers, mutate a global JVM configuration or claim that a
fault injected through reflection is an application behavior.

Test templates are generated by the EXISTING M3HashPinnedJavaSnapshotRecipe with
module-relative src/test/java paths; execution root is m3/indexdb, not repository
root. Generation parses Java LSTs, checks reviewed output hashes, refuses conflicts
and reaches a second-pass fixed point. No parallel parser/recipe engine is added.
The workflow is owned by the existing hash-pinned PlainText recipe, since YAML
is infrastructure text here rather than a Java source transformation.

The focused workflow executes the real inherited Maven tests and0.99 coverage
check. Reports are retained on failure so the next repair targets observed misses.
It does not skip tests or coverage, install into the supplied JDK, or claim a
whole-JDK/product completion. Pin the candidate commit in every receipt.

## Scope and pattern/IOP roles

The production observation scope is MODULE; writes are additive test/resource/
workflow paths. Store, codec and graph remain existing canonical owners.
The three test classes are ContractProbe participants, template assembly is
Template Method composition through existing OpenRewrite atoms, and the CI job
is a proof adapter. No new database, hash, grammar or parser ownership is created.

## Acceptance

Exact source/template identity; strict Java21 compilation; real JUnit execution;
0.99 line and branch gate unchanged; real OpenRewrite generation/replay/no-overwrite
tests; no production-source diff. A passing test suite with failing coverage is
reported as precisely that, not as completed admission.
