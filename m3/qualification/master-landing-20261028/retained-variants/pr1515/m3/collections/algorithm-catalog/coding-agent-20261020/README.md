# Coding-agent recipe catalogue

The coding agent selects a known recipe, exact options, source-bound scope and proof DAG. Existing recipes and action owners do the work. This extension adds 101 source-inspected bindings (87 upstream Recipe classes, six canonical mechanical entries and eight existing check/fix/recheck actions), plus 417 required-capability rows across 31 categories. It extends the preserved 844 intent rows and 63 shapes; counts are different layers, not a total number of validated executable operations.

Start with PROGRAMMING_REQUIREMENTS.tsv, look up candidate IDs in RECIPE_BINDINGS.tsv/JSON, bind options, resolve exact input paths and all allowed effects through SCOPE_CONTRACT.json, then select a shape from RECIPE_DAG_SHAPES.json. Each DAG node still needs its own real executor. Unbound rows are search obligations and typed gaps. No agent may fill an unavailable recipe by silently emitting product implementation.

The inventory includes documentation, Javadoc requirements, interfaces, annotations, Java refactoring, arrays/masks/collections, JNI, concurrency, build/dependencies, configuration, data/IO, testing, scoring/static analysis, security, performance and Git/PR-stack delivery. Interface helpers are explicitly separated from invocable Recipe classes. Finding source names or regex candidates is not proof of fit or execution.

SCOPED_RECIPE_EXAMPLES.yml contains four real declarative configurations for synthetic fixture paths: exact-file documentation regex replacement, folder search, annotation attribute update and ordered Java cleanup. They use existing OpenRewrite classes/options. Maven discovery/application is NOT_RUN; MAVEN_INVOCATION.json binds the actual plugin5.23.1 properties/goals and records the offline cache and output-routing prerequisites. This data packet is not a generic JSON dispatcher, new plugin, shell-command permission or registered MCP surface.

Regex follows Java Pattern/Matcher. Both text Find and FindAndReplace can convert matching structured trees to PlainText; separate text and AST stages with a checked reparse. The experimental FindMultiselect flag handling has a source-visible defect and remains held. REGEX_CONTRACT.json records replacement escaping, Unicode, zero-length, deadline and fresh-parse fixed-point checks.

Scope is enforced by actual input maps, selected recipe options/preconditions and complete effect guards. Ordinary preconditions do not fence scanning or generated files. Narrow repairs in SealReplay still guard the complete five-target manifest. Widening repeats all admission gates. ai provider selectionPath currently does not bound iteration; FILE locality is not a file-count boundary.

M3JDK21 remains one Java/HotSpot/JNI product. Existing public interfaces, contracts, behavior and licenses remain mandatory. Canonical reusable recipe custody is Synexia; product postimages and runtime admission belong to receiving forks. STRING remains the global receiving phase; this catalogue grants no phase promotion or PR merge authority.

Validation here checks source hashes/options, references, duplicate IDs, required-option bindings and acyclic example graphs. It does not claim execution of the 101 bindings or the four YAML examples. Separate M3JDK21 proof receipts identify the source-bound actions that actually ran. Storage protection remains ACTIVE.

Current requirement coverage is 105 bound candidates and 312 unbound requirements. Candidate binding still requires fit and execution; this does not claim 417 available executors. PREPARATION_VALIDATION.json records the earlier frozen preparation and its then-current hashes; CATALOGUE_VALIDATION.json is the current payload manifest.
