# Catalogue-driven wrapper and JNI convergence

This additive receiving record connects actual M3JDK21 files to the existing
Synexia recipe owner and accumulated algorithm decisions. Read PLAN.md for the
frozen product, interface and storage scope. FOSS_REUSE_DECISION.tsv records the
selected and rejected donors by problem category. ECLIPSE_INPUTS.tsv pins the
existing Claude/Eclipse inventories and handover without treating recognition
marks as source review or completed UI transformations.

Search this catalogue with the existing tools:

```sh
rg -n 'FILTER|SORT|STABLE|INDEX|JNI|COW' m3/collections/algorithm-catalog/wrapper-convergence-20261020
rg -n 'REJECTED|DEFERRED|PENDING' m3/collections/algorithm-catalog/wrapper-convergence-20261020
```

A behavioural atom is a meaningful, independently verifiable operation:
strict mutation refusal; owner-dispatched bulk removal; ordered predicate
composition; equal-run index reversal; bounded native scan; backend-symbol
admission. These are not arbitrary method-size limits or per-entry objects.
All previous catalogues and rejected candidates remain in place.

`VALIDATION.md`, `JAVA_QUALIFICATION.json` and `OWNING_SUITE.json` retain the
executed candidate checks and their exact scope. Canonical transformation and
final receiving receipts belong to the existing Synexia dataset identified in
`PLAN.md`; the catalogue is a searchable target record, not a second engine.

## Review decisions that must survive the next pass

The old M3FilteredLists cursor-probe candidate is rejected: a lazy List can throw
on an unrequested read, and a valid LinkedList.subList can mask invalidation at
an exhausted or empty boundary. The original implementation is retained. The
diagnostics directory holds runnable baseline and rejected-candidate witnesses.
The existing comparator-origin and read-only iterator-generation findings also
remain pending an actual owner boundary; replacing them with a different
callback schedule is not a contract-preserving refinement.

The Eclipse bundle ordering donor adds three new public methods. It is retained
as a reviewed candidate for a separately scoped interface decision, while this
pass preserves the existing public interface. The M01-M33 source recognition
matrix is a discovery input, not a blanket instruction to ban loops, impose a
method-length cap, or change original Eclipse API contracts.

The proposed java.base and libjava files preserve their actual Apache notices
from the existing product PRs. Their core-intake review remains explicit in
m3/docs/name-mapping.json. The installed derived-image proof compiles and loads
the pinned product String/native closure, using the recorded Temurin HotSpot;
it does not establish a fully source-built HotSpot, cross-platform readiness,
licence admission or promotion of the global STRING receiving stage.
