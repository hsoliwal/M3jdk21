## Source-level decision

The current private sorted owner and public navigable compatibility type have lost the
historical explicit `removeFirst` and `removeLast` guards. Their inherited JDK21 defaults
inspect the source before refusing mutation; empty results throw `NoSuchElementException`,
and nonempty/hidden results can evaluate user predicates. This violates the owners' already
documented unconditional read-only contract. The baseline tests reproduce the actual defect.

Restore the two guards in both existing owners. Restore the historical private
`SortedSetView.reversed()` atom using
`readOnlySortedSet(SortedSet.super.reversed())`, plus the covariant private
`NavigableSetView.reversed()` delegation to `descendingSet()`.

The open PR 1503 uses `new SortedSetView<>(sorted.reversed(), predicate)` instead. That
candidate is not adopted because changing the traversal owner can change predicate/comparator
callback demand. The selected historical guarded-JDK reversal reuses an existing guard class
and produces an exactly equal ordinary-read callback tape against current master.

The guard adds an explicit wrapper at the reversed-view API boundary, with no element snapshot,
per-entry retained structure, payload clone, JNI callback, native method or new storage owner.
This is a contract restoration; no throughput, retained-memory, or universal platform
performance improvement is claimed.
