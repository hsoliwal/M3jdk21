## Refined atoms

It costs at most 32 extra primitive payload bytes per plan, plus array header; the existing byte-accounting method is updated truthfully. Construction uses word intersections, not repeated scalar scans. A temporary final-state mask is construction-only.

Java `repeat` and JNI `repeat0` now compute state-function powers most-significant-bit first. Original immutable input plus result/scratch replace three owned working rows with two. Count zero/one behavior, absorbing -1, range/state/count validation, output alias refusal and native release discipline remain. Existing compose/buildPacked operations and callable/JNI descriptors remain. Java default dispatch is unchanged.

## Tradeoffs, not blanket speed claims

Measured Java repetition allocation fell 432 -> 288 bytes/call at 64 states, 1584 -> 1056 at 256, and 24624 -> 16416 at 4096: one fewer array. Explicit native scratch payload drops from 6S to 4S bytes, excluding JNI and allocator overhead.

Timing is mixed. For 4096 states/Long.MAX_VALUE, Java median rose 250224 -> 267955 ns in the exploratory probe. Dense negative acceptance became much cheaper while cold plan construction increased. The catalogue retains these costs; no end-to-end JDK speedup or new JNI dispatch selection is asserted.
