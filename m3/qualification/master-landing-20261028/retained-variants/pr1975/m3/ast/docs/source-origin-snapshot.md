# M3AST source-origin snapshot (provenance wire contract)

This is a bounded, deterministic **sidecar** for the existing `M3SyntaxOrigins` owner.
It does not serialize M3File source bytes, foreign parser trees, Java object graphs,
semantic bindings, caches or native handles. M3AST retains the six-method foreign
syntax adapter and its original flattened occurrence/green-node representation.

## Wire frame

Version 1 is big-endian: 8-byte `M3ORIGIN` magic, 32-bit version, 32-byte
`M3SyntaxTree.projectionSha256` seal, 32-bit row count, 32-bit distinct source
count, and an insertion-ordered source dictionary. Each dictionary element is a
32-bit UTF-16-unit length, the exact UTF-16 code units of its logical source ID,
and a 32-byte SHA-256 digest of the *external* physical image. Each row is six
signed 32-bit lanes: generated byte start/end, dictionary index, original byte
start/end, and `M3SyntaxOrigins.Relation` ordinal. A 32-byte SHA-256 over all
preceding packet bytes is appended. Even the zero-origin packet is canonical.

Strings retain literal Java UTF-16 units rather than platform charset encoding,
normalization or replacement. Range bounds are **physical bytes**, not Java
`char`/UTF-16 indices, and are half-open. Source-ID tables must be unique,
ordered by their first row use, and contain no unused entry. Rows must be in
nondecreasing generated-start order. Source generations, grammar and syntax
shapes are bound by the projection SHA-256 seal.

## Boundaries and failure policy

`M3SyntaxOriginsSnapshot.encode(origins, maxPacketBytes)` writes an immutable
byte array subject to an explicit byte budget. `decode(packet, tree, maxRows,
maxSources, maxPacketBytes)` clones the untrusted packet, checks the checksum,
format/version, projection, dictionary and row budgets; constructs the **existing**
primitive-backed `M3SyntaxOrigins`; then requires a byte-for-byte canonical
re-encode. Unknown relations, stale source versions, duplicate/unused/reordered
source identities, truncated packets, trailing data and unrepresentable ranges
are rejected. The packet SHA-256 protects accidental integrity, **not** authenticity
or trust of external sources.

**Critically:** decoding only proves that metadata matches the supplied syntax
projection. It does **not** prove the claimed original physical bytes.
Before promoting `EXACT_BYTES`, the consumer must use
`decoded.verify(tree, id -> sourceOwner(id).bytes(), maxSources,
maxRetainedBytes)` with actual M3File source generations. `Verified.exactAtByte`
refuses derived or overlapping macro/embedded origins; callers never infer an
original point by guessing a parser-specific mapping.

This preserves source attribution/licensing metadata as source IDs and SHA-256
seals, but does not itself determine the upstream license. Review donor licenses
and external provenance separately. Implementation is original Apache-2.0 code;
parser concepts are informed by Clang source locations, Roslyn green/red syntax,
Tree-sitter byte spans and OpenRewrite lossless source handling. No donor code
is copied.

## Qualification

The canonical Maven/OpenRewrite recipe and hash-pinned input/output records live
only in `hsoliwal/com.synexia`. M3JDK21 receives generated Java postimages,
JUnit tests, and this data-only contract. The source-only Java 21 fixture runs
versioning, canonical refusal, malformed physical UTF-8, randomized source spans,
4096 distinct source identities, and a genuine JDK compiler parser plus M3File
immutable generation cross-owner test. OpenRewrite SDK, original module/jlink,
installed-JDK/jtreg and performance acceptance are independent gates.
