## Initial candidate rejection

Independent review found that the initial broad `IllegalArgumentException` fallback
can retry a throwing comparator or swallow an opaque owner's overridden range
exception. The initial `M3FilteredViews` source remains **rejected**. The corrected
successor uses explicit owner admission and does not catch or retry that exception.
`M3NavigationFailureContract` passes 140 checks, including nested wrappers and empty
owners. `REJECTED_CANDIDATES.json` retains the rejected source, protected probe and
failure logs, and links the completed corrected candidate proof. The initial
recipe integrity pass never supersedes this behavioral counterexample.

## Behavioral atoms and correction requirements

- **Filtered navigation:** preserve the external read-only direct-navigation path
  and use an actual stored neighbor as an endpoint only through
  an explicitly supported owner path; an arbitrary `IllegalArgumentException` is
  not a bounds signal. Keep original visibility decorators on traversal and
  preserve comparator and opaque-owner exception demand. Exact JDK tree owners,
  their JDK-owned range/key views and final M3 tree owners are admitted. Opaque
  decorators and custom subclasses retain their original query range operations;
  bounded-query enhancement is not claimed for that domain. A comparator may place null between non-null elements. JDK entry
  presence and Guava iterator scans inform the review; Guava's unchanged query-based
  narrowing is insufficient for every bounded view.
- **Strict read-only views:** guard sorted/reversed/sequenced/default and endpoint
  writes, including empty and no-op calls, before invoking mutation callbacks.
  Reading remains with the original owner. Known private read-only filter chains
  use depth-sized predicate metadata instead of recursive wrapper frames. Predicates
  retain order and exception identity; membership retains its repeated representative
  probes and is not claimed to become constant or linear in depth.
- **Long index projections:** reuse the current value/address/index owners for
  physical mask paths. Switching an already sorted direction reverses equal-value
  groups while preserving occurrences within each group: O(n) time and O(n) output
  indexes. Encounter-order sort remains O(n log n). This comparison is an algorithm
  cost model, not a measured speedup.
- **Int/long path masks:** add full signed 64-bit row IDs without narrowing physical
  offsets or mask words. General selection remains two passes, O(n*s), with O(k)
  detached output. After mandatory geometry validation, same-stage required/forbidden
  overlap can reject all and all-zero masks can admit all. Total validation still
  costs O(n+s); zero masks do not mean an invalid zero-length stage directory is
  accepted. Bounded identity windows preflight exactly the consumed coordinates and
  reject aliases of all metadata directories before writes.
- **JNI:** retain the existing int entry point and add a long entry point around
  the same region-based gather owner. NATIVE_REQUIRED retains explicit missing-library
  refusal, including empty/constant calls. No Java predicates, retained Java pointers,
  critical-array pins or new per-row object stores are introduced. JNI region-call
  overhead is material; this parity implementation is not claimed faster than Java.
