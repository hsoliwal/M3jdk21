## Resulting behavior

Qualified catalog opening uses full specification/source/rank/projection seals.
Canonical dense ranks resolve through primitive shard/row coordinate lanes,
even when physical text order differs. Canonical sorting remains solely a
UnicodeX authority. Concept X, frequency rank and physical position are distinct.
The existing M3File manifest carries full pins beside the SMFILE01 image
through existing RAW_BYTES objects and relations; qualified token-range operations validate every declared
language before the existing generation and image checks. Legacy local APIs are
unchanged. Unknown pieces, whitespace and exact UTF-16 remain available through
existing owners. This is not a new general ID-only M3FMT wire decoder, a production
dictionary publication, or publisher authentication.

Derived `M3IndexedLiveView` ranges and reversals enforce the root's strict
read-only policy. No-op mutations and invalid argument/callback precedence are
explicit bug repairs. Resolved method signatures remain, with one newly declared
`subList` override and changed private wrapper identities. Existing parent arrays,
primitive permutations, stable ordering and invalidation remain authoritative.
Repeated reversal cancels opposite descriptors. The separate core
`jdk.internal.m3.M3IndexedView` policy is unchanged.

Java/JNI masks keep both original scan symbols and add bounded state-only count.
Native capability checks resolve both scans; missing/partial libraries refuse
explicit native requests. Count capability is independent, so an older two-scan
library still supplies scans. Native calls retain the selected two-condition
predicate, bounded scratch, range checks and exception handling.
