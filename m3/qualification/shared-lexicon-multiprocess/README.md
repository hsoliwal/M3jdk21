# Shared lexicon image: two-process qualification

This additive Maven/OpenRewrite crate installs one QA probe; it changes no production storage, API, wire format or image admission rule. It reuses the existing `SharedLexiconImage` and the existing hash-pinned Java snapshot recipe. Synexia remains the canonical recipe donor; M3JDK21 receives the exact generated test and its qualification packet.

The input manifest declares the probe ABSENT. Recipe tests require exact Java AST output, fixed-point replay, duplicate refusal, wrong-AST refusal and refusal after scanner-time drift. An additional source contract checks the diagnostic boundary. The existing engine and its dependencies are referenced by immutable Git blobs, not copied or modified here.

The process probe creates one sorted version-1 fixture with 139 records, including empty text, composed/decomposed spellings, Devanagari, supplementary characters and isolated UTF-16 surrogates. Each reader runs five JUnit tests: exact arena copies; lookup/lower-bound/prefix reference comparison; directory coordinates and mapped code units; read-only/resident mapping; and independent arena ownership. The load/isLoaded APIs are advisory: both readers reported a false hint while the subsequent native samples reported Valid resident pages. Mapping inspection uses reflection only in QA. Strong reachability is retained until the parent releases both processes.

The parent holds a read-only file handle with FILE_SHARE_READ, refuses preexisting fixture paths, and keeps the backing file locked against later writers/deletion during observation. Both live reader PIDs, full-file hashes, image identity, directory digest, actual mapping filenames and volume/file ID are recorded. Windows QueryWorkingSetEx inspects each reader's actual mapping address: Valid, Shared, ShareCount and protection. The entire small image must fit one page at aligned mapping offset zero. ShareCount is OS-reported sharing; it does not identify physical PFNs or prove that the counted peers specifically name these two JVMs. Samples are sequential, not atomic.

Exported records still copy bytes into LocalM3Arena. This proof does not establish shared Java arrays, direct mapped String backing, fixed virtual addresses, permanent residency, JVM startup/throughput improvements, JNI parity or other platforms. It does not resolve the separately pending manifest-metadata Unicode acceptance choice.

The sealed Windows qualification uses the existing Java 21 RAM compiler and Maven 3.9.14, offline read-only dependency tails, an approved writable S: head and 47 hash-pinned JARs. Recipe replay and fixture creation run through Maven; two direct Java reader processes use the same sealed compiler/packet. Compiler classes, packet transport and logs stay in RAM. At most one 4 KiB fixture is live. Child JVMs must be reaped and the image hash rechecked before deleting only this run's fixture. Crashes and unknown outputs are retained for diagnosis rather than broadly cleaned.

Read `qualification-input.references.json`, `qualification.py` and `proof.json` together. The crate includes the byte-exact bootstrap POM/Java driver and stdin loader used for execution; Maven's exec.args override is recorded in the proof. The bootstrap POM's default execution is historical and is not a claim that unconfigured mvn test runs this packet. Restore each referenced source from its named Git blob, verify SHA-1 as a Git blob, then compact-JSON encode the specified property order plus LF to reconstruct the sealed input. The exact RAM driver and POM are separately pinned. No online dependency or corpus fetch is part of qualification.

Initial harness correction: the first attempt omitted the preinstalled Snappy DLL selector, so the storage watchdog stopped it before image creation. Its exact duplicate cache DLL was compared byte-for-byte with the retained read-only copy, its hash recorded, and only that task-created duplicate removed. The corrected harness explicitly verifies and reuses the installed library; failed-attempt evidence remains linked. A second candidate wrongly asserted isLoaded() must return true. Its failure is retained; the final recipe instead tests the documented load identity contract, records the hint and retains all native page-sharing requirements. This is not a claim that the first attempt stayed within its planned transient allocation.
