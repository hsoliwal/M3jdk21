# Language corpus manifests: absent-period round trip

An Artifact constructed with period=null is valid and stores period="". Canonical serialization writes the required twentieth column with an empty value. The reader previously decoded that value to an explicit empty String and passed it to the strict constructor, which rejects explicit empty periods. Thus an accepted artifact could not survive public writeNew/read.

The reader fix converts only the exact empty period wire column back to the existing null constructor input. Present values retain the original decoder and validation. The column remains mandatory; blank/multiline/invalid/noncanonical encodings still refuse. The public constructor continues to reject explicit empty strings. No header, schema, canonical bytes, root, source IDs, mapping identity, language scope or acceptance policy for Unicode metadata changes.

The migrated source already exists at m3/core/src/jdk/m3/text/M3LanguageCorpusManifest.java. Two existing closed-world recipe registries did not yet recognize that owner. The composition registers only this exact path in M3ScopeInference and M3HashPinnedJavaSnapshotRecipe; neighboring names, case variants and the unregistered source-receipt neighbor remain rejected. The existing Java recipe engine generates each registry change serially; the qualified new engine then generates the reader change. Each stage binds exact before/after hashes and preserves every unrelated source byte.

There are eight recipe JUnit tests per stage: typed replay/fixed point, missing owner, duplicate owner, wrong AST, source drift, post-scan drift, exact frozen atom and old/scope-only/full owner-admission states with neighbor refusals. The product qualification runs before/after/after/before in four fresh Java 21 JVMs. Each product run contains ten JUnit tests covering all five corpus planes with absent periods, mixed absent/present periods, exact present code units/whitespace, strict constructor refusals, malformed/missing columns, canonical wire refusals, writeNew idempotence/collision, defensive canonical bytes, five original write-free refusal methods and the complete original M3LanguageCorpusManifestTest main. The full refusal test's multi-file persistence main is not run.

All dataset values are synthetic custody metadata. No external dataset bytes are downloaded, validated or admitted. The period is an existing optional metadata string, not a new calendar/date grammar. Exact dictionary/source/tokenization/generation bindings retain their current owners.

The original full test main is size-checked before invocation and owns one manifest file. Other tests create one source-sealed owned fixture at a time, delete only their exact fixture after each action, and verify zero retained file allocation at stage completion. Input seed and canonical root comparisons are stable across before/after runs. Each fixture fits one4096B S: cluster. The existing545MiB task cap and8GiB reserve remain active; F:/C: source/cache inputs stay read-only.

The qualification uses the existing offline Maven/Java RAM compiler and47 pinned JARs. Private/no-save JVM PerfData options are inherited process-locally and asserted by product JVMs. Compiler output, transport and logs remain in RAM. Read qualification-input.references.json, qualification.py and proof.json together. Resolve immutable Git blobs and adjacent resource references in property order, compact-JSON encode UTF-8 plus LF, and verify the sealed input. Bootstrap POM/driver and the actual exec.args override are pinned; unconfigured mvn test against the historical bootstrap POM is not claimed to run this packet.

The change is bounded maintenance using existing source, validation and rewrite owners. No new product API, storage architecture, native library, corpus payload, performance claim or arbitrary Java-path prefix is introduced. Java/JNI/full-JDK/reactor/other-platform qualification remains separate. Existing Apache-2.0 notices are preserved.

Registry composition uses fresh compilation between stages; it does not hot-replace the running OpenRewrite class. The work order is the frozen pre-execution input; ADMISSION_DECISION and proof carry the executed qualification status.
