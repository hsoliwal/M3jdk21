# Unselected candidate: version-1 image first-touch hash elision

**Selection: NOT_SELECTED_PERFORMANCE_GAIN_UNPROVEN. Runtime source is unchanged.** The complete recipe and experiment are retained for catalogue reuse; the explicitly invoked recipe produces a candidate only. No default recipe activation or runtime installation is part of this PR.

Opening an M3LEX version-1 image computed javaHash for every record even though only version 2 has a stored Java-hash lane. The result was discarded. The recipe moves the existing pure helper behind the existing version-2 guard. It preserves version 2's original payload-before-stored-lane evaluation order. All image identities, bounds, ordering, SHA-256 checks, corruption detection, byte ownership, public APIs and physical image formats remain unchanged.

This removes one Java-hash scan over the UTF-16 payload on version-1 admission. Opening still performs its existing full-image and per-record integrity work; this is not an O(1) startup or lookup claim. No retained metadata, pool, key, wrapper or native library is added.

The canonical Synexia recipe uses the current hash-pinned Java snapshot engine unchanged. Its manifest binds one existing production owner and exact before/after hashes. Seven recipe tests cover replay, fixed point, missing owner, duplicates, wrong AST, source drift, after-scan drift and the exact bounded textual change. Tests share some cases in one method.

Product qualification compiles the six exact production owners plus the original SharedLexiconImageContractTest fixture builder and this crate's QA adapter. It executes before/after/after/before in four fresh Java 21 JVMs. Each run has eight JUnit tests: unused v1 calls, retained v2 calls, v2 operand evaluation order, exact UTF-16 identity/lookup, malformed-image refusals, post-admission record corruption, missing SHA provider refusal and public file-open/copy behavior. The baseline intentionally fails only the unused-v1-work discriminator. The original filesystem-heavy test main is not invoked.

An isolated QA-only ASM class loader adds one counter increment at javaHash(I)I entry. It retains all six owner class definitions together to preserve package/sealed-type relationships. The counter is absent from the shipped source and from behavior/timing measurements. A separate unmodified-bytecode check asserts the v2 constructor calls javaHash before reading the persisted hash. Version 1 must drop from 139 calls to zero; version 2 must retain 139 calls.

The uninstrumented real constructor is also timed on two bounded direct-memory images containing 8,192 records each, with two warmups and five samples per format per JVM. Per-thread allocation is sampled when supported. Raw samples are retained; this diagnostic does not prove mapped-file I/O, JVM startup speed, whole-application throughput, statistical significance or other-platform performance. JIT/provider/host load effects remain possible.

Every stage runs through existing offline Maven/Java RAM compilation with 47 pinned JARs. A single 2,236-byte public-open fixture consumes one 4 KiB S: cluster; compiler class files, source packets and logs remain in RAM. The approved 545 MiB task cap and 8 GiB reserve remain mandatory. The owning child process exits before the exact fixture is removed.

Read qualification-input.references.json, qualification.py and proof.json together. Resolve immutable Git blob sources and adjacent crate resource leaves, preserve JSON property order, encode compact UTF-8 JSON plus LF, then verify the sealed input Git blob. The exact existing Maven POM, RAM compiler driver and stdin loader are included; Maven exec.args overrides are in the receipt. The historical bootstrap POM's default phase is not a claim that unconfigured mvn test runs this packet.

The first attempt's generic storage guard aborted a replication without recording the exception type or violated dimension. A later diagnosed run exposed a 64 KiB hsperfdata file while the 4 KiB fixture was live. That process ended with zero retained task files. The final harness sets process-local JAVA_TOOL_OPTIONS to PerfDisableSharedMem=true, UsePerfData=false, PerfDataSaveToFile=false for all descendant JVMs, and asserts those effective VM flags. The cap was not raised. Its partial result and zero-retained-output audit are retained. The harness now records precise failure details and boundedly rescans if a transient directory entry disappears during accounting; storage limits are unchanged. A preceding functional candidate was also rejected by parent review because its v2 comparison operands reversed the original mapped-read order. The final template and call-order discriminator preserve that order.

Existing Apache-2.0 and Guava notices remain intact. ASM 9.6 is an existing hash-pinned QA dependency used through its API, not copied or newly required by production; its [BSD-3-Clause license](https://asm.ow2.io/license.html) applies to that library. The existing six M3 owners and original test helper remain their sole source owners.

The completed final experiment did not demonstrate a runtime gain. Its v1 median was 10.85625 ms after versus 9.74430 ms before; median thread allocation was 6,301,816 versus 5,921,832 bytes. V2 control timings also shifted. This short diagnostic cannot prove a general regression, but it does not satisfy selection of a speed optimization. Keep current production source; preserve raw results and improve representative measurement before reconsidering.
