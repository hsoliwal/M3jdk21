# LangDex receipt numeric validation

The existing private numeric helper parses the signed-long range first, then checks canonical ASCII spelling in the original input instead of rendering a new decimal String. Nullable markers, negative source IDs, duplicate/null row custody, exact parse/canonical error ordering and open-stream lifetime are preserved. This class verifies source receipts; it does not admit rows to an M3 catalog or authenticate the producer.

The runtime afterimage and both JUnit fixtures are byte-identical to the qualified canonical Synexia recipe resources. [Synexia PR #17327](https://github.com/hsoliwal/com.synexia/pull/17327), commit `fe763f135ebde000f0c6a497e4bc9386cb72c9ec`, retains the three independently qualified recipe stages, exact preimages/afterimages, Maven POM and pinned offline classpath, original test co-input, RAM compiler driver, input resource views, catalogue/donor decisions and complete executed logs. RECIPE.json binds those sources and proofs. Recipes continue to live exclusively in Synexia.

Six JUnit tests run through M3EnvelopeNumberQualification on each of four fresh before/after/after/before JVMs. Each run matched 923,736 behavior checks. The test calls the existing m3/core/test/LangDexSourceEnvelopeTest.java unchanged and adds signed extrema/overflow/cause checks, all UTF-16 units in three numeric positions, seeded spellings, matching-digest public-wire cases, competing invalid-field precedence, stream lifetime and API/field shape. Matching digests prevent checksum failures from masking numeric-validation defects. Compile the production owner, existing original test and these two fixtures together with Java 21 and JUnit Jupiter/Platform; the pinned canonical RUNTIME_QUALIFY.py and RUNTIME_INPUT.resources.json supply the exact executed harness. New test sources are qualification fixtures, not JDK runtime dependencies. This PR does not change CI workflows.

PERFORMANCE.json retains all warmed public-receipt verification samples. For 1,024 concept-link rows, median allocation fell from 788,512 to 665,632 bytes per verification (15.6%). Timing ranges overlap; the after median was 1.7% slower. No latency improvement is claimed. This measures neither startup/retained heap nor real corpus admission, JNI, OS shared storage, cross-platform behavior or a full JDK build. Strict lossless raw/profile/catalog admission and the separately prepared Windows filesystem tests remain incomplete. No source-ID substitution or missing precompute synthesis occurs.

OpenJDK Long.parseLong is a source reference only. No OpenJDK implementation was copied or relicensed. Existing Apache-2.0 headers and Hitesh Soliwal/Synexia attribution remain intact.
