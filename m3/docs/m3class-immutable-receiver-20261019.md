# M3Class: immutable class metadata, 2026-10-19 scoped receiver

The product is **M3JDK21**, not a separate M3 library on top of stock Java. The
canonical runtime owners are already in java.base:
`jdk.internal.mindex.M3Class`, `M3CI`, `M3CB`, `M3Boundary`, `M3Member*`, `M3PC`.
The public, VM-created `java.lang.Class<T>` remains the authoritative identity
and behavior API. This receiver does not add any new public Class type or wrapper
dependency, nor does it claim `java.lang.Class` has been natively rerouted.

## Immutability contract

`M3Class` has only `final M3CI owner` and `final int row` fields. Equality is
owner identity and row, not binary class name. Immutable M3CI primitive lanes
hold names, flags, hierarchy, member descriptors, CSR offsets/postings and
structural hashes. The optional JVM resolution boundary holds weak Class/loader
references; no strong live Class/loader/member graphs persist in the snapshot.
`M3CB` sessions separately handle epoch and invalidation.

**A frozen snapshot is not an immutable live VM definition.** Dynamic loading,
JVMTI redefinition/retransformation, agent changes, hidden-class lifetime and
unloading require explicit lifecycle rules and invalidation before any cached
fact becomes authoritative. No verified automatic lifecycle hook exists in
this receiver.

## This scoped change

Previously `M3CI.classRow(loaderSpace, name)` called `classRows(name)` and
copied matching postings to a temporary `int[]` on each lookup. This edit
uses `findText` + `Arrays.binarySearch(nameKeys)` and traverses
`nameOffsets/nameRows` directly. It preserves same-name distinct
class-loader spaces and leaves `classRows(name)` defensive-copy behavior
intact. The source, test and SHA-256 manifest are generated by Synexia's
Maven/OpenRewrite hash-pinned recipe:

- Target jtreg: `test/jdk/jdk/internal/mindex/cb/com/m3/cb/M3ClassRowLookupTest.java`

## Exact migration family

| Synexia origin | Existing M3JDK21 owner | Further admission required |
| --- | --- | --- |
| MIndexClass | M3Class + M3CI | VM lifecycle and consumers |
| MIndexClassBoundary | M3Boundary + M3CB | Hook/invalidation proof |
| MIndexClassIndex | M3CI | Rich detached classfile index |
| MIndexClassMetadataIndex / signatures / annotations | No equivalent complete port | Preserve type-use targets, generic grammars and descriptors |
| MIndexClassfileParser / multi-release JAR | No equivalent complete port | No class initialization, source release and classpath order |
| MIndexClassImage / ImageCodec | No equivalent complete port | Deterministic mmap/read-only image, fail-closed validation, JNI/native policy |
| MIndexClassPerfHarness | No complete image benchmark | Process isolation, CPU/heap/mmap measurement |

Donor provenance: Synexia PRs #3980, #3981, #3982, #4071 and #4075.
**Compatibility warning:** `synexia-indexstring` image `MIndexMemberKind`
ordinals differ from the `M3MemberKind.code()` lane. Explicit format
mapping is mandatory before receiving .midxc files.

## Pending qualification

1. Synexia Maven recipe replay, fixed point, source-drift/refusal tests.
2. Full M3JDK21 configure/make image, JDK jtreg `CBProbe` and
   `M3ClassRowLookupTest` in interpreter and JIT modes.
3. GC/ClassLoader unload and JVMTI redefinition/retransformation probes;
   JNI and module access checks; CDS and JIT compatibility.
4. Measured allocation, lookup latency, retained heap, native memory and
   preparations vs steady-state usage on the same JVM/workload.
5. Broader MIndexClass donor comparison, status mapping and class-consumer
   acceptance; no promotion by merge ancestry alone.

This is a **draft, nonpromoted Class receiver atom**. The canonical
M3JDK21 stage order is String -> arrays -> collections -> AST/compiler /
remaining families. Class inventory and research are allowed ahead, but
Class runtime promotion is blocked until preceding stage seals and gates
permit it. No full migration or benchmark win is claimed.
