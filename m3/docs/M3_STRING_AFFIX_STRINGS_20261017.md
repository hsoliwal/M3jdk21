# M3 String affix precompute, row-regex integration and java.util.Strings

Source-first canonical recipe: [Synexia #12017](https://github.com/hsoliwal/com.synexia/pull/12017) (commit 10ef2f71069ea835e3fcd8804dbc377cff25ada5). This M3JDK21 receiver installs exact first-party SHA256-sealed Java 21 sources. No Synexia runtime dependency, second payload store, HotSpot/JNI ABI change, public `String` signature replacement or parser clone.

**Before:** M3StringRegexRowPrecompute prepares mandatory character posting masks, then scans eligible rows for zero-flag prefix/suffix/exact literal regexes even when the query is sparse.
**After:** new java.lang.M3StringAffixPrecompute optionally owns ten primitive int[] rank/parent/interval lanes (40 bytes/row). Source is a cloned frozen M3String[] directory; each M3String retains canonical atom/range identity. Ordinary UTF-16 and reversed UTF-16 rank intervals answer prefix/suffix candidates in O(log n * query length + result-ordering), but do not answer arbitrary substring matches. No object-based trie nodes or duplicated character payloads.

Existing row executor builds this sidecar only after four qualifying prefix/suffix/exact prepared queries and >=64 rows; uses sparse (<=50%) ranges, restores source row order and intersects existing char-bitset necessity facts. Memory admission limits sidecar to 32 MiB and available heap; failure retries on bounded 128-use intervals. Dense, cold or unsupported inputs use the unchanged current Java route. Exact JDK Pattern/Matcher evaluation remains authoritative for nonliteral regexes, newline behavior, captures, flags, surrogates and all unsupported patterns.

New public `java.util.Strings` is an additive **M3JDK-specific** utility family, analogous to Objects/Arrays/Collections. 27 documented overloads/methods cover null/blank/default handling, common UTF-16 prefix/suffix without surrogate splitting, padding/repetition, prefix/suffix removal, delimiter operations, case-insensitive search, reverse and strip. Existing String/indexOf/substring/regionMatches APIs are the execution owners, so M3 String optimization can be reused. No third-party source copied; API donors include Guava, Commons Lang and Spring.

Exact source-extracted stock Java21 proof: **298,077** affix geometry checks, **1,138,124** regex row/Pattern checks, **120,037** patched java.util.Strings checks. Product CI re-runs source-extracted oracles against the actual receiver Java source and SHA256 seals. Added jtreg candidates are compiled for Java21 syntax; execution on a custom-built M3JDK21, JNI, GC/JIT/CDS, JCK, stress and A/B throughput/allocation/cost measurements remain unqualified merge gates.

Future source-first port candidates (distinct index semantics, avoid duplicate owners): frozen suffix-array substring coordinate index, FST/DAFSA compressed lexicons, Aho-Corasick multi-pattern automata, composable DFA state-transfer summaries, exact positional postings, reversible text traversal, Unicode normalization/codepoint facts and bounded language-pack metadata. Reuse Synexia IndexSubstringIndex, IndexNGramIndex, M3RegexDp and Lucene FST donors as appropriate, preserving applicable licenses.

## Diagnostic CPU A/B and measured admission frontier

The source-extracted Java21 fixture now includes `AffixRankBeforeAfter.java`, executed by CI: 4,096 frozen M3 String-shaped rows, zero-flags `ab.*` query, and identical 132 row IDs before/after. On the original local Java21 fixture, best of five repetitions of 2,000 candidate requests was 10.21 ms for existing scan/posting path versus 2.87 ms for prepared rank interval (~3.56×). This is **not** a speedup claim for native M3JDK21; it excludes affix build, uses mock canonical ownership, and is sensitive to hardware/JIT/corpus. It establishes a reproducible before/after A/B harness for promotion decisions. Full source-built JDK baseline/modified JMH, allocation, RSS, GC and JNI tests remain merge gates.
