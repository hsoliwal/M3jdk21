UnicodeX JNI: native/langdex/langdex_jni.c is the implementation, while src/main/native/langdex_jni.c includes it. For stable inputs, source review found agreement on zero-unrestricted / any-overlap masks, signed bit 63, inclusive confidence, range duplicates and result coordinates. Caller-owned count/into APIs are Java-only. Native filtering uses 1024-row blocks and a fresh result array; count-changing mutation checks are not a full concurrency guarantee. Library loading alone does not prove export completeness. Critical-array acquisition can copy, so logarithmic comparisons do not prove logarithmic total JNI cost. Block boundaries 1023/1024/1025, stale-export loading, signed masks, confidence -1/499/500/501/1001, alias and capacity refusals remain targeted native discriminators, not executed proof here. Source blobs are in catalogue/algorithms.tsv.

Identity bridge: M3LangDexSourceEnvelope verifies wire evidence and intentionally accepts null IDs / repeated rows. This is not admission. UnicodeX M3JdkLangDexIdentityProjection rejects empty/null individual scope IDs but does not prove batch uniqueness; SharedLexiconCatalog already rejects duplicate source/record mapping keys. Keep original IDs and reject ambiguity before admission. Wire SHA, canonical-byte SHA and domain-separated identity digest are different; the latter two do not authenticate SourceScope. Projection normalizes glottocode, restricts surfaces, omits the opaque row source field and accepts revision labels unlike the envelope's 40-lowercase-hex revision. Therefore it is not yet a complete lossless transport/admission bridge. Important future fixtures include null and duplicate IDs, decimal IDs above 2^53, normalized glottocode with original spelling retained, distinct record IDs sharing canonical identity, and duplicate versus distinct concept links.
