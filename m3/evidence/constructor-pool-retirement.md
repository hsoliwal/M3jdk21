# Constructor-pool experiment retired from the product path

Source pin: OpenJDK jdk-21+35, `890adb6410dab4606a4f26a942aed02fb2f55387`. Isolated test runtime: Temurin 21+35-LTS, Linux x86-64. No installed JDK was replaced.

V1 was a real java.base module patch, not a wrapper. It retained 256 direct-mapped arrays of at most 256 payload bytes. It passed narrow semantics, but injected lazy class-initialization OOME poisoned the helper and subsequent String construction. A discoverable class monitor could block all eligible constructors. It allocated the defensive copy on every call and was slower in the synthetic warm constructor test. It is not applied here.

V2 required explicit post-bootstrap activation off constructors. A default-null volatile reference published fully constructed state; constructors used original copies while state was absent. There were no constructor catches, initialization, retries or cache monitors. Optional dependency setup and metadata-allocation catches were scoped; arbitrary errors propagated. It passed 72 fresh-JVM focused fault/recursive/paused-setup/held-monitor runs (two restarts across four compiler/compact configurations and nine scenarios). The original deterministic semantic digest matched in eight v2 runs with GC dedup enabled/disabled. This did not establish full compatibility or benefit.

The comparison used 100,000 warmup constructions, then a separate timed loop of 100,000 constructions from the same prepared 53-char array. Activation/input preparation, warmup, operation wall/CPU time, allocation, and GC-assisted retention were reported separately. No per-operation preparation was added. Three fresh forks per configuration used G1 with 128 MiB heap and dedup age threshold 1. Allocation stayed 9,600,440 reported bytes per measured loop in every configuration. After separately timed GC assistance, stock G1 dedup retained one or two arrays (53 or 106 payload bytes), compared with one for the custom pool. The custom pool's warm construction remained slower. There is no observed speed break-even or justification for constructor integration.

Raw original and v2 logs, source recipes, hashes and full caveats are retained in the versioned Library evidence bundle. This file summarizes the decision rather than distributing a patched String.class. This repository's String and HotSpot sources remain unchanged at the pin.
