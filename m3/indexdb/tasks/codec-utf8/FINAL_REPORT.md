# Semantic codec repair

One existing package-private implementation is changed. There is no new public
API, parser engine, functional interface or database. The new test types are
CodecProbe, CodecTest and CodecRecipeTest; existing names are not silently renamed.

## Delta
Standard Java21 charset adapters reject malformed UTF-8 and unpaired surrogates.
They do not normalize Unicode; valid U+FFFD remains valid. Payload-relative long
arithmetic validates advertised counts before capacity allocation and reserves
remaining prefixes and fixed records before text reads. Encoder byte limits now
agree with the existing decoder limits. Invalid-input rejection is an intentional
MODULE contract tightening, not a claimed behavior-identical refactor of bad data.

## Executed
The original and repaired eight-class DB source sets plus CodecProbe compile
with --release21 -Xlint:all -Werror. The original accepts malformed metadata with
different re-encoded bytes and substitutes unpaired surrogates. The repair rejects
both. A24-byte header advertising50million strings, nodes or edges produces OOM
in three separate original32MB JVMs; the repair rejects all three without OOM.
No OutOfMemoryError is caught to manufacture validation success.

128 valid Unicode snapshots generated by the pinned original compare byte-for-byte
with the repaired encoder and round-trip through it. Their ordered golden corpus
hash is d972971c21142f82252f5cb912f7c17fee34af248767df251175228aa402c594.
The JUnit test embeds that original-derived hash, not a self-generated oracle.

## Recipe and pending gates
The existing M3HashPinnedJavaSnapshotRecipe owns the module-relative3-target
crate, including the original preimage. Four JUnit recipe tests are supplied.
The existing database workflow owns real JUnit and unchanged0.99 coverage checks.
Local Maven/JUnit/OpenRewrite execution is not claimed. CI receipts must report
test pass separately from coverage failure. No gate or original test was removed.

## Reproduce
Run the existing DB module:
`mvn -B -ntp -f m3/indexdb/pom.xml clean verify`

For the independent small-heap fixture, compile CodecProbe with the real DB classes,
then run `java -Xmx32m -cp <classes> com.m3.indexdb.CodecProbe count 12`.
Positions16 and20 test node and edge counts. Use modes malformed, surrogate or
fixtures <fresh-dir> for the other probes.

Apply the recipe from m3/indexdb in a fresh admitted source workspace. API/source
parser, SQL, JNI, complete transactional guarantees, performance, total memory
quotas and whole-JDK completion are not established by this repair.
