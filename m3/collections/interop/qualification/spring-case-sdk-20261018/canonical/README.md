# M3 five-provider SDK: source-sealed Spring indexed-casefold factory

This is a bounded **source-first** improvement to M3JDK21's existing optional `m3/collections/interop` SDK. It does not attempt to reimplement the already installed `M3SpringCaseInsensitiveMap` (M3JDK21 #1220, Synexia #12213), or override the more direct parallel-array `M3LinkedCaseInsensitiveMap` proving branch #1269.

**Actual incremental result:** add the typed `M3LibraryCollections.springCaseInsensitiveMap(Locale)` factory returning a `java.util.Map<String,V>` whose storage remains entirely the existing two `M3LinkedHashMap` slot/index owners. Add a 23rd `sdk-family-bindings.tsv` record, update exact factory-count tests and SDK family table, and add JUnit integration checks for typed factory, original stored representative, null-value keySet removal and reflection-level signature/owner verification. The factory does not claim that this class *is* Spring's concrete `org.springframework.util.LinkedCaseInsensitiveMap`, whose nominal type, serialization and subclass hooks are not replicated.

**Recipe-first:** reuse the already-installed Maven/OpenRewrite `M3HashPinnedJavaSnapshotRecipe` in Java AST/LST mode for three exact MODIFIED Java source/tests plus one ABSENT integration test. Reuse Synexia `M3HashPinnedTextSnapshotRecipe` for exactly two pinned TSV/Markdown owner metadata changes. The source templates, original preimages, exact SHA-256 manifest and negative/refusal/fixed-point Maven JUnit test are committed before any target product file changes. If a candidate is incorrect, fix and rerun the original recipe.

**Donors:** first-party M3 original indexed collection storage under Apache-2.0, Spring Framework 6.2.0 provider binary (no copied implementation), and available writable/user-owned Guava, Eclipse Collections, Apache Commons forks as pinned donor evaluation workspaces, with their original licenses intact. No cloned foreign runtime is added to `m3/collections` core. Candidate categories include hash lookup, locale folding, mutable views, absent/null mappings and state-mask JNI separation. See `CATALOGUE.tsv`.

**Executed locally:** Java21.0.12.1 strict `javac --release 21 -proc:none -Xlint:all -Werror` against exact original M3LinkedHashMap Git blob `ade59880b8c9b2bee1b32ae67ca9d29b7382d998` and real `spring-core-6.2.0.jar`, `spring-jcl-6.2.0.jar`. A separately authored candidate that implements the same Map-level contract (not an exact blob of the existing M3 class) passed 480,510 assertions / 12,000 randomized operations in both tiered JVM and `-Xint`. Exact installed Spring class was previously qualified by Synexia #12213 / M3JDK21 #1220; do not attribute local candidate counts to it.

**Not run locally:** actual Maven/OpenRewrite SDK replay (Maven unavailable in current container), new factory JUnit against *all five pinned provider JARs*, current full reactor, exact-head hosted C17 `-Xcheck:jni`, installed source-built JDK/jtreg/JCK, serialization, cross-version JMM and any CPU/heap speedup comparison. Review remains DRAFT/HOLD until each of those gates is actually observed. The active String -> arrays -> collections -> AST/compiler promotion policy is not advanced.
