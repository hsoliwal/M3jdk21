# M3JDK21 Apache Commons Collections 4.5.0 Bag retained-count receiver

M3JDK21 is the standalone Java/JNI product, not a stock JDK with an added M3
library. This receiver changes only the original `M3ApacheBag` production
semantic atom and installs proof artifacts generated by Synexia; the
`M3CountedBag`, `M3LinkedHashMap`, dynamic array, offsets, masks, and JNI
storage/API stay original.

## Root cause and pinned donor evidence

Actual exact-head M3JDK21 five-library JUnit workflow
[39779077003](https://github.com/hsoliwal/M3jdk21/actions/runs/39779077003)
ran **158** real tests (5 failures, 1 error) including the
`M3ApacheBagContractTest.randomizedOfficialHashBagOracle` failure at
randomized step **702**, expected zero stored occurrences but M3 returned two.

The actual pinned dependency is `commons-collections4:4.5.0`, NOT an
unspecified newer donor. In Apache
`rel/commons-collections-4.5.0` original source
`org/apache/commons/collections4/bag/AbstractMapBag.java`
(Git blob `9da508f625f5ab6050c56b2da465e8aac4e448e2`), the
`retainAll` requested count **greater** than its owned count selects the
unconditional `else` and removes all stored occurrences. Apache's later
`master` uses `else if(otherCount==0)`; adopting that newer behavior is
not compatible with this pinned 4.5.0 dependency.

M3's original semantic atom kept both owned elements in this case. The
source-sealed correction uses `requested > owned ? owned : owned - requested`
for the removed count, reproducing exactly the 4.5.0 versioned behavior.
