# Synexia M3 recipe-first receiving invariant

Every LLM-assisted source task must create or reuse a Maven transformation recipe, qualify it, execute it, and verify the generated changes. Repair recipes and rerun; never hand-patch their output. Preserve public interfaces, sealed contracts, observable behavior, donor notices and append-only evidence. Decompose by replaceable behavioral atoms only when this improves reuse or proof; recipe counts and arbitrary fragmentation are not objectives.

Consult the canonical algorithm catalogue before each per-file pass. Record the candidate, problem category, exact donor and license, complexity assumptions, contract differences, rationale and executed proof. Keep GitHub implementation provenance distinct from LeetCode/HackerRank/GeeksforGeeks problem-category evidence. The receiver catalogue is a sub-ledger of the existing Synexia bag crate, not a second algorithm authority. Query with `java com.m3.collections.tooling.M3CountedCatalogue catalogue.tsv frequency`.

The Maven recipe suite rejects missing/drifted/duplicate preimages, modified templates, Java-as-text substitution, uncatalogued Java targets, and unsafe delivery paths. Three existing storage owners use exact preimage hashes and unchanged public signatures. Native/text paths are relative to the collection module; Java paths are repository-relative. Materialization validates the complete target set first and requires an exclusively owned checkout. Individual replacement is atomic where supported; multi-file delivery is not a transaction.

FILE -> PACKAGE -> MODULE -> REACTOR/API promotion remains serial and proof-gated. This receiving slice does not promote STRING phase, replace java.base, qualify a full installed JDK, or override historical manifest/JNI/release gates. Develop must never be rebased or force-pushed.

Native invocation is explicit after loading a trusted library. The aligned count inputs must be stable during Java/JNI calls. The JNI kernel owns bounded scratch and one result, not an interner or new collection owner. No native speedup is claimed without end-to-end measurements including alignment and boundary costs.
