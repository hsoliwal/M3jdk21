# Five-provider M3 count/flag restoration — qualified convergence recipe

The exact base is M3JDK21 `master@2f2beb2eff7a88f1f7c0012fd17a78a6f0a00b49`. Canonical Synexia source owner is `com.synexia` append-only develop, no rebase or direct default-branch mutation. The target product is the public separately built Apache-2.0 `m3/collections` and optional `m3/collections/interop` Maven modules.

**Observed regression:** current optional interop still references `M3ObjectCounts`, but the class is absent on target master; `M3FiveProviderFlagSelection` calls three constructors that no longer exist. This prevents a source-level five-provider SDK compile. The new additive owner and its original JUnit contract test are copied **byte-for-byte** from previously fully qualified [M3JDK21 PR #1174](https://github.com/hsoliwal/M3jdk21/pull/1174), commit `88ff3b3dd2756bcfe964cad443e46378447a657d`. No lost count/flag optimization is silently replaced.

Existing newer `M3CountedBag`, `M3GuavaMultiset`, `M3EclipseBag`, and `M3ApacheMultiSet` APIs are retained. The Guava and Apache adapters gain additive shared-owner constructors. The Eclipse class continues to serve the exact Eclipse `MutableBag` interface but delegates its count operations to the existing M3 counted owner, preserving its public methods. `M3FiveProviderFlagSelection` obtains selected 32-bit state masks from the restored existing M3ObjectCounts JNI path, then builds one shared live count owner for all three provider facades; independent JDK and Spring projections retain their own API semantics. Captured flag metadata is immutable; count state is shared and mutable, so snapshot capture temporarily holds the counted metadata of one selected M3ObjectCounts and one mutable M3CountedBag. No per-occurrence node/Entry objects or new JNI symbols.

All seven source outputs are SHA256-sealed in `manifest.tsv`; four original source preimages are kept in `preimages/`. The original proven `M3GpuToolJoinRecipe` / `M3GpuToolJoinManifest` code is mirrored exactly; one minimal class selects this task's source templates. The genuine Maven/OpenRewrite JUnit suite executes generation, then fixed-point, missing, drift and named-YAML checks. Generated production and test files are exact template blobs; no hand-patched output. If failures arise, revise the canonical recipe/postimage and rerun.

**Readiness:** exact template/source SHA checks and historical donor tests are available. Java21/current-master, actual provider jars, Maven/OpenRewrite execution, checked native JNI and JDK integration are required at this new exact target head before promotion. Historical #1174 success is not transitive to this branch. Correct providers: OpenJDK/JDK, Google Guava, Eclipse Collections, Apache Commons Collections and Spring Framework. There is NO blanket full-library coverage or universal benchmark claim.
