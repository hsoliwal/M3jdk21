## Contract and target mapping

Exact first-party Apache-2.0 postimage templates are received into the existing
`com.m3.collections` module: Java `M3IndexPathMasks`,
`M3IndexPathMasksSelfTest`, JUnit adapter `M3IndexPathMasksTest`,
optional JNI C17 `m3_index_path_masks.c`.
The **preexisting** `M3IndexMaskCompactor`, `M3FilteredViews`,
`M3MutableFilteredViews`, `M3FilteredLists`, `M3LongSortedViews`,
and public JDK `java.util` contracts are not changed.

- Dynamic-array owned rows + logical-to-physical `int[]` index/offset maps.
- First/count/signed stride (including reverse) index paths, input bounds checked.
- Multiple left-to-right pure metadata stages over full **32-bit integer words**:
  every required bit present, no forbidden bit present; reject at first failing stage.
- Preserve upstream order and duplicates. Detached exact `int[]` result; no
  per-row object, Entry, boxing or staged-result array. Early first-index query.
- Caller preserves stable input arrays for the duration of the operation. Not
  itself a live filtered/sorted wrapper or concurrency/snapshot guarantee.
- JNI Region-only primitive reads, no retained pointers; opt-in separate
  `libm3_collections_pathmask.so`, explicit absence failure, no speedup claim.
