# M3 Collections — array offsets, index permutations and state bit masks

**Canonical convergence owner:** `hsoliwal/com.synexia`, `synexia-m3-recipe/recipes/m3-state-mask-arrays-20261017/`.
**Product receiver:** `hsoliwal/M3jdk21`, independent Apache-2.0 `m3/collections` module.
**Boundary:** one additive primitive-metadata helper and one differential oracle; no existing JDK/HotSpot/JNI source, public collection signatures, serial form or Synexia runtime dependency changes. Does **not** advance ordered String → arrays → collections promotion.

## Data/metadata ownership

- Canonical element/object payload stays in existing owner (`long[]`/`Object[]` and GC traceability as applicable); no object/node/Entry is allocated per metadata row.
- `int[] rowSlots` selects physical slots; `byte[] stateBits` stores eight caller-defined state flags **per aligned occurrence**, not eight global object states.
- `M3SlotAllocator28` continues to own stable generational handles and live membership; `M3BitLane28` continues to own sparse single-bit flags. This helper is **not** an allocator, payload owner, lifecycle governor, or concurrency primitive.
- Slot `0` is valid and repeated IDs are retained. The returned compaction bound, not a zero sentinel, determines logical size. State bits may require explicit physical-slot alignment by their concrete owner; this helper expects **logical occurrence alignment**.
- `compactWindow` is a stable LeetCode #27/#283 read/write specialization that moves both metadata lanes in O(n) time with O(1) scratch, zeroes only rejected window-tail entries, and preserves outside-window content.
- `rotateWindow` is a LeetCode #189 three-reversal specialization for aligned indexes and flags; accepts signed distances including Integer.MIN_VALUE and never moves element payloads.
- `update` modifies caller-owned unsigned-byte masks, validating disjoint set/clear bits before writes. `matches` validates required/forbidden flags. No universal `LIVE`/`PINNED` lifecycle implications are assumed.
- Detached mask selection delegates to the **existing** `M3IndexMaskCompactor.select` Java/JNI engine with its explicit `NATIVE_REQUIRED` refusal and bounded `Get*ArrayRegion` peer. JNI is not used for scalar mask updates/rotation/compaction.

## Reproduce on a Java 21 Maven/GCC environment

```sh
mvn -B -ntp -f m3/collections/qualification/m3-state-mask-arrays-20261017/recipe/pom.xml verify
java -cp m3/collections/qualification/m3-state-mask-arrays-20261017/recipe/target/classes \
 com.synexia.m3.M3StateMaskArraysRecipe --check .

mkdir -p /tmp/m3-state-mask-classes /tmp/m3-state-mask-lib
javac --release 21 -Xlint:all -Werror -d /tmp/m3-state-mask-classes \
 m3/collections/src/main/java/com/m3/collections/M3IndexMaskCompactor.java \
 m3/collections/src/main/java/com/m3/collections/M3StateMaskArrays.java \
 m3/collections/src/test/java/com/m3/collections/M3StateMaskArraysSelfTest.java
java -cp /tmp/m3-state-mask-classes com.m3.collections.M3StateMaskArraysSelfTest
cc -std=c17 -O2 -Wall -Wextra -Werror -fPIC -shared \
 -I"$JAVA_HOME/include" -I"$JAVA_HOME/include/linux" \
 m3/collections/src/main/native/collections/m3_index_mask_compactor.c \
 -o /tmp/m3-state-mask-lib/libm3_collections_mask.so
java -Xcheck:jni -Djava.library.path=/tmp/m3-state-mask-lib \
 -cp /tmp/m3-state-mask-classes com.m3.collections.M3StateMaskArraysSelfTest
```
