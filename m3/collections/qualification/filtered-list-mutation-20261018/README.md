## Defect and bounded correction
At M3 base `f29b0afe7ad253cc0562bc8dfdd48fc1acec710e`, delivering 2 from `[2,4]` and then inserting 6 at physical index zero lets filtered cursor remove delete 6, set overwrite 6 and add use the stale coordinate. Original JDK cursor controls refuse without another write. The reviewed candidate adds a private reversible cursor check before the three existing backing-list writes. Keeping those writes matters: CopyOnWriteArrayList is writable while its iterator is not.

No new public API, field, payload store, Entry/Node graph, JNI symbol or Eclipse framework. The source owner, logical/physical index mapping, optional writes, predicate validation, hidden elements, duplicate/null occurrences, late binding and sorted/sublist/reversed composition remain as before. This is not a guarantee of thread safety or every custom List's callback/transport semantics. An exhausted cursor can allocate a backing exception; no performance superiority is claimed.

## Receiving order and commands
The first commit contains recipe mirrors and qualification only. Runtime/test output is received in a later commit only after real SDK execution succeeds. `mvn -B -ntp -f m3/collections/qualification/filtered-list-mutation-20261018/pom.xml test` consumes `target/pre/M3FilteredLists.java`; copy the preserved `pre/M3FilteredLists.java.txt` there first. The SDK tests emit actual SourceFile results into `target/generated/`, after exact hash and fixed-point assertions. Workflow separately compiles/runs those outputs and checks the original remains red. Once received, it requires all three product files to be byte-identical to those SDK outputs, then compiles and executes the actual receiver too.

The scoped POM uses the published OpenRewrite 8.17.1 SDK and does not change the owning module's source-vendored dependencies. It is not full reactor/Maven/native/JNI/installed-JDK acceptance.
