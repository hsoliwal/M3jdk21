# Original M3JDK21 live filtered/sorted physical viewport page

M3JDK21 is the integrated Java21/JDK/HotSpot/JNI SDK, **not** a runtime wrapper over a JDK. This receiver is stacked on [M3JDK21 #1791](https://github.com/hsoliwal/M3jdk21/pull/1791), after its parent-owned array-mask rank and JNI viewport page/frame convergence.

One original production source: `m3/collections/src/main/java/com/m3/collections/M3IndexedLiveView.java`. The original backing `M3ArrayList` owns one `Object[]`; the live view's private `int[] physical` retains only selected/sorted positions. Previously `physicalIndices()` always detached the full int directory. New **package-private** `copyPhysicalWindow(firstOrdinal, maxCount, destination, destinationOffset)` reuses the exact bounded-copy algorithm already present in the sibling `M3IndexedListSnapshot`, subject to original `refresh()` and invalidation rules. It copies just the resident page, with no per-row Entry/Node, no user predicate/comparator re-evaluation when prepared, and no JNI call for an already prepared small page.

The new method validates nonnull destination, physical source index, count and destination bounds before writing. It limits output to remaining selected elements and uses one primitive `System.arraycopy`. Zero output writes nothing, duplicates and stable ties remain in the original order, parent mutation invalidates the cached index through its current epoch and repeated sorted/filter callbacks retain prior behavior. All pre-existing public List methods, `physicalIndices()` defensive clone behavior, Java/JNI exported symbols, UI data models and native renderer contracts remain untouched. Complexity: **O(selected source) for an existing dirty refresh**, then **O(page)** for the copy; no asserted total O(page) on dirty views.
