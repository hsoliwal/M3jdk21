# M3JDK21 indexed/keyed parallel collection receiver

Synexia is the convergence workspace. This M3JDK21 receiver ports source-pinned first-party Apache-2.0 atoms from hsoliwal/com.synexia at `2f9a579c60a41422f5b164049cf65746a0830713`. No copied challenge solutions or new Entry/Node storage trees.

**Keyed operations.** A client explicitly supplies `M3Parallel.by(orders, Order::customerId)`. Equal-key callbacks execute sequentially in captured order within a strict terminal; disjoint groups may overlap. `mapOrdered` restores source positions, not global effect order. Other operations include byInt, byRange, byKeys, byReadWrite, stable mask/filter and top-k, associative reduction, sorted duplicate joins, key-local windows, synchronous bounded batches, quiescent async and weighted plan caching. Client callbacks remain Java-side; Java is the default backend and JNI is explicit.

**Physical representation.** A growable `Object[]` captures source references once; existing `M3LinkedHashMap` assigns key IDs; a compact primitive `int[]` stores offsets then stable row IDs, while masks control stable selections. Views never acquire per-item `Entry` or `Node` objects. Cache privately specializes pinned M3/Synexia slot atoms. Native C++17 kernels use checked JNI array-region copies for integer scatter and primitive min/max windows.

**Receiver refinement (not in source donor).** `captureOnce` traverses each Collection exactly once using iterator without `size()` or `toArray()`, including lazy filtered/sorted wrappers. The overload with a row budget rejects the first over-limit element before invoking read/write selectors. Encounter ordering, key semantics, masks and native ABI are unchanged. A bounded callback/executor cannot provide cross-call locking, retries, rollback, or implicit associative reductions. Concurrent source mutation and key mutation remain caller responsibility.
