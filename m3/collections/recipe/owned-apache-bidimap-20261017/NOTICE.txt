M3BidiMap protocol adaptation
Copyright 2026 Hitesh Soliwal and contributors

The Apache AbstractDualBidiMap mutation, inverse, setter and view bulk protocols
are adapted from commons-collections commit 7f7fb0244abc940a2e9dd28b67508c0483a58c3e,
Git blob c99878d0446429cd1677e32f8ed58cb5ab500009, under Apache-2.0.
The original Apache source header and product notice are retained.

Storage is composed from the unchanged first-party M3LinkedHashMap public API,
Git blob ade59880b8c9b2bee1b32ae67ca9d29b7382d998 at M3jdk21 commit
e913ab89056657eca4009678cfe9a657c020e79b, Apache-2.0.
No Apache provider implementation superclass or instance is used.

Qualification boundaries and preserved source quirks:
- For a still-resident entry, Entry.setValue returns the installed value;
  MapIterator.setValue returns the old value. Detached entries are not admitted.
- Duplicate setter checks use key reference identity, including equal distinct keys.
- Values retains the provider collection-identity equals/hash behavior despite Set API.
- Empty-view removeAll(null)/retainAll(null) return false; removeIf(null) returns false.
- Standard Map default methods route through this owned mutation/entry protocol.
- Guarded view mutations keep both M3 owners in sync; raw array-entry setters retain
  the provider reverse-maintenance bypass. Values iterate forward key encounter order.
- Retained entries or iterators after external structural mutation, serialization,
  reentrant callbacks and the complete Commons Collections library are not admitted.
Actual qualification belongs to the root-run pinned provider oracle and its receipts.

The pinned AbstractCollectionDecorator inherited dispatch is retained using owned
M3 API view descriptors (blob 493ff732764698abe64b156c1f6a40b24a54ac04): add/addAll,
containsAll, isEmpty, size, toString and toArray()/toArray(T[]) delegate to the owner.
The generator-array default reaches that typed overload. Raw entry-array setValue
returns the previous value and bypasses duplicate checks/reverse maintenance.
forEach, Set.spliterator, stream and parallelStream retain guarded iterator entries.
Final targeted/full provider qualification and source-byte freezing remain required
after this correction; source custody itself establishes no new behavior proof.
