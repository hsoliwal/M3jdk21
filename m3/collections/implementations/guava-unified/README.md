# Single-source Guava API closure: M3 HashMultiset and ArrayListMultimap in one artifact

Canonical recipe: `com.synexia.m3.UnifiedGuavaMultisetAndListMultimap20261027`, held exclusively in `hsoliwal/com.synexia` as exact Java21 Maven/OpenRewrite source-sealed template postimages; M3JDK21 only receives product Java/JUnit/metadata, not recipe code.

**Why:** Two independently source-closed standalone modules each contained the same original `com.google.common.collect.Multiset` FQCN and could not be co-loaded. This unified module receives the **identical source only once**, together with the Apache-2.0 original Guava 33.4.8 `Multimap` and `ListMultimap` interfaces, plus both *already existing, independently owned* M3 implementation classes. All source is copied byte-exact from canonical Synexia Guava API crates or exact product master owners; no Guava implementation source is imported. FQCN public methods/erasure preserved, but Guava's JSpecify/GWT/ErrorProne annotations and default spliterator behavior not universally metadata-identical; record as HOLDS.

Storage is both actual M3 algorithms: `M3HashMultiset` uses dense `Object[]` plus `int[]` counts/hash/generation/index; `M3ArrayListMultimap` uses dynamic `Object[]` segments, primitive ordinal directory/hash/index/order/count arrays and mask lanes. Entry-shaped objects only at required Java API return boundaries; no retained per-element objects or new JNI symbols. This is one compile/runtime artifact: `com.m3.collections:m3-owned-guava-unified`. Public Guava API source appears exactly once in the jar, neither implementation has another Maven runtime dependency and `jdeps` should report java.base.

The full original `M3HashMultisetContractTest`, `M3HashMultisetDifferentialTest`, `M3ArrayListMultimapContractTest`, `M3ArrayListMultimapDifferentialTest` are also received byte-exact and run together with a new cross-family test. The real Guava 33.4.8 JAR is *test-only* for the 96k + 96k existing seeded differential runs and class-specific JaCoCo. Original M3 implementation classes must still satisfy 99% line and branch coverage, with only original Guava API interfaces excluded from that first-party threshold. No external Guava runtime jar or Maven compile dependency may enter the published JAR.

**Packaging rule:** The unified module supersedes the two previous **standalone/candidate** API-closed Guava artifacts *for combined use*. Do not deploy the separate jars or stock Guava with the unified jar in one classloader/JPMS module layer; they contain conflicting original public types. Previous candidates are not deleted or forcibly rebased. A future target-owned migration/packaging recipe must declare the unified artifact authoritative and exclude the candidates from installed images.

**Scope:** This still implements only real `HashMultiset` and `ArrayListMultimap` API families, not every Guava type or all five upstream libraries. Java21 compile, JUnit, `jdeps`, Maven no-vendor-runtime graph, exact source seals, serialization and module/classloader collision gates are separate. No installed M3JDK21 image/hosted acceptance or performance superiority claim without evidence.
