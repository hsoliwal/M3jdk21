The adapter admits the entire source set before the first write and replaces files serially through atomic per-file replacement. It requires a single writer with no concurrent target-path changes. It is not a transaction across the whole file set: a mid-apply I/O failure can leave a mixed sealed PRE/POST state, which exact replay can subsequently admit. The regression cases prove refusal of preexisting drift and symlinks, not protection from a concurrent path-replacement race. Product receiving is a separate serial step using these qualified Results and a fresh source binding; its logs accompany the receiving checkout.

## Reproduction

Use Java 21 through `JAVA_HOME`, Maven, Python 3, and a Linux C compiler. From the canonical crate:

```sh
mvn -B -ntp -Pcontract -Dm3.contract.target=/absolute/path/to/M3jdk21 verify
python3 receive.py --target /absolute/path/to/M3jdk21 --check
python3 receive.py --target /absolute/path/to/M3jdk21
python3 receive.py --target /absolute/path/to/M3jdk21
```

The public mirror carries the four unchanged SDK owners under `sdk-owner/src/main/java`; pass `-Drecipe.owner.root="$PWD/sdk-owner"` to Maven there. Use a fresh contract output directory, or preserve the previous evidence before `mvn clean`. Retain current SDK Results, reports, and input binding before receiving. Historical logs record their actual execution paths and do not configure a portable run.
