## Comparison decisions

Guava supplies a close comparison for live filtering and sorted backed ranges. The inspected Collections2 owner combines filters over the underlying collection, while Predicates preserves callback order and short circuit. Its pair conjunction retains the two predicates, so this review does not infer a binary-carry depth bound from Guava. The selected depth-bounded atom is already first-party. Guava's filtered generic collection iterator is unmodifiable, which does not supply the writable bidirectional List cursor contract required here. Collections2 also evaluates contains against an equal query; the first-party stored-representative tests have a deliberately more specific contract.

Eclipse Collections supplies a useful separation between lazy selection and eager selected collections. SelectIterable retains the adapted iterable and its predicate. SelectIterator caches the next accepted element and refuses remove. TreeSortedSet.select creates a separate comparator-preserving set. Those operations help identify the semantic categories, but substituting them would lose the existing writable List cursor or change the lifetime and uniqueness of the result. The implementation source links and exact blobs are in the donor ledger.

The retained first-party sorted range views inherit the backing comparator and remain backed. The retained sorted List snapshots are detached, stable, and preserve duplicate element occurrences and representative identity across comparator ties. These two lifetime contracts remain distinct. The precompiled Pattern test exercises an opaque CPU callback through deep live filtering; it does not make that callback a GPU program.
