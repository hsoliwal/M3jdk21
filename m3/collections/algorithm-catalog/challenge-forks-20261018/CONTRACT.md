## Forks and convergence workspaces

The user explicitly authorizes treating forks as convergence workspaces. A fork
can host exploration, donor comparison and reusable transformation work under the
same contract-preserving discipline as an original repository. Workspace identity
does not by itself establish algorithm suitability, source rights, or receiving
qualification. The existing canonical M3 recipe workspace is referenced by role;
this packet does not change its ownership or expose private source.

Include only fork rows whose retained repository metadata explicitly states
`private: false` and `visibility: public`. Carry exact parent/source, branch and
head identities, preserve `READ_ONLY_CANDIDATE`, and distinguish a branch name
from implemented code. Public metadata evidence is projected to the fields
required for these rows. Private repository rows, private source inventories,
private commit bodies, restricted URLs and broad mixed-visibility search/list
responses are excluded from the public packet.
