## Serial candidate plan

1. **Projection stable-group reversal.** Adapt only the private
   `reverseValueGroups` atom and opposite-known-order branch from historical
   M3jdk21 #1164 (`9b7620f592248e858628c2489866ec73227d519c`) and its canonical
   Synexia #12156 (`0d595c9a1b6578bede85e2a3c9cb5025c91bcefc`). Both historical
   projection payloads have Git blob `114d6bff738ffeee0c432637538b482ef856e60c`.
   Read payload values through the current address kernel. Reverse contiguous
   equal-value groups while copying each group's index IDs in forward order,
   confined to `[from,to)`. This uses one result `int[]`, O(n) traversal, and no
   payload copy. Keep same-direction sharing and the existing encounter-order
   merge implementation byte-identical. Update only the class cost description
   to distinguish the two paths.
2. **JNI candidate v1: reject.** The historical two-word decision-mask/prefix
   compaction loop emits once per admitted source region. The current owner
   batches up to 128 selected IDs across regions, so a one-hit-per-region case
   would increase output JNI calls by up to 128 times. The historical loop also
   precomputes an entire decision region even when an early selected value fills
   a small output limit. Its old single-export file cannot replace the bounded
   current file. Historical stack/allocation receipts are not current proof.
3. **JNI candidate v2: suffix-only row read.** Retain the current first-match
   scan, all-pass/contradiction shortcuts, pending output batch, predicate loop,
   cursor, validation and both exports. After `first_match < take` is proved,
   fetch `(next + first_match, take - first_match)` instead of `(next, take)`;
   read the corresponding local value at `i - first_match`. Since
   `0 <= first_match < take <= end-next`, both the narrowed region and index
   rebasing remain within the original region. Rejected prefixes have no
   observable row reads other than native transfer cost. This does not add
   native storage, callbacks, pointers, JNI calls, decisions or output writes.
4. **Actual-owner proof.** Add a standalone deterministic Java oracle, adapted
   from the existing first-party #12156 and bounded-window proof shapes, covering
   short exhaustive stable sort/filter/slice compositions, split tie groups,
   alias/ownership checks, all 65,536 mask pairs, byte/chunk/window boundaries,
   bounded and legacy cursors, output guards, repeated resumes and explicit
   missing/old-native behavior. Expected sort order uses stable boxed JDK sort;
   expected scan progress uses an independent scalar loop. It executes actual
   owners; no production substitutes or random sampling.
5. **Resource proofs.** Extend the existing native region-count fixture, preserving
   its original cases, to count transferred elements and unchanged calls for
   rejected, dense, sparse-tail, nonzero-offset, bounded-tail and early-limit
   cases. This instrumented JNI table measures region work only; real JVM/JNI
   tests remain the correctness gate. Add a standalone actual-owner resource
   probe for thread allocation/CPU, retained heap and Linux RSS/VmHWM, with cold
   setup separate from warm sort and sparse/dense/bounded scan workloads.

## Gate ownership and status

This subtask prepares templates and proof sources only. It does not invoke a
compiler, test, resource probe, shared-library build, Maven or OpenRewrite. Every
candidate is `PROOF_REQUIRED` until the parent executes the ordered gates on
exact preimages: documentation -> patch -> lint -> compile -> tests -> runtime,
then source/API/JNI identity and zero-change recipe replay. Baseline and candidate
must run the same new proof. The region-work proof has explicit `--baseline` and
`--candidate` expectations so observations cannot be confused. No elapsed-time
speedup, current allocation total or native transfer result is claimed before
execution. Keep the historic #12156 receipts as lineage only.
