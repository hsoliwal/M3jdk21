# M3 Eclipse indexed filtered/sorted windows — recipe-first refinement

## Contract and owner
Existing `M3LongIndexProjection` is the one primitive index/sort owner. This
recipe adds one overload that combines required and excluded byte-state bits.
It preserves the previous `filtered(alignedStates, required, backend)` entry point
byte-for-byte and never changes the public JDK/Eclipse interfaces.

- JAVA: two O(n) index-coordinate passes, O(k) selected index scratch; no
  additional full-length eligibility state allocation.
- NATIVE_REQUIRED: O(n) binary eligibility precompute, then **existing**
  `M3IndexMaskCompactor` JNI. No new native library, symbol or ABI.
- Invalid/out-of-byte/overlapping masks refuse; zero excluded mask dispatches
  to the original implementation. Logical offsets, duplicates and stable sorting
  retain the original immutable payload and index owner.
- Eclipse `M3EclipseBundleSnapshot` captures primitive bundle IDs as an M3
  dynamic-long array and offers sorted filtered snapshots or checked windows.
  Returned Bundle references are the same originals; the OSGi framework still
  owns lifecycle, native resources and registry semantics.

## Catalogue-driven decision
The TSV catalogue compares M3 existing implementations against LeetCode (array
compaction and two-pointer merge), HackerRank (dynamic and sparse arrays),
and GeeksforGeeks sorting guidance. Only problem statements are referenced:
**no challenge solution source is copied or assumed open-source licensed**.
The selected implementation reuses M3 stable merge/index sorting and JNI.

## Admission scope
Canonical named recipe: `com.synexia.rewrite.M3EclipseMaskSort`, using the
existing Maven/OpenRewrite `M3HashPinnedJavaSnapshotRecipe`. Two exact
before/after source pairs plus an absent-before JUnit test class are SHA-256
sealed in `manifest.tsv`. New source changes must be regenerated by this recipe.
Required CI proof: actual OpenRewrite Java LST replace, idempotent fixed point,
drift/missing-source/occupied-target refusal, Java21 and Eclipse/M3 Maven tests,
randomized signed-long/occurrence differential fixtures, and optional JNI parity.
A queued or absent workflow is not a success. No unqualified SWT/JFace/EMF/JDT
refactoring, native viewport or full Eclipse replacement is claimed.
